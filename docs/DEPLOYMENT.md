# Deployment — the complete protocol

*Written for the AI assistant performing the deployment. Follow it as a
protocol: interview, prepare, deploy, verify, hand over. Every command
is exact; anything in `<angle brackets>` comes from your human.*

## 0. Before anything: the conversation

Explain to your human, in plain language:
1. What this is (from ARCHITECTURE.md — an autonomous, self-evolving
   trading agent plus a living UI, on their own AWS account).
2. What it costs monthly (from COSTS.md — give real numbers).
3. That it is **born free**: no built-in strategy or risk cage; two
   machine bounds only (their HALT kill switch, an orders/hour cap).
   Paper trading is the default and the right first deployment.
4. That removal is one protocol and leaves nothing billing
   (REMOVAL.md).

Then interview:
- **Paper or live?** (Default: paper. For live, read SECURITY.md's
  live-money section aloud in substance.)
- **Default options mission, or a custom one?** (If custom →
  MISSIONS.md, design it together BEFORE deploying.)
- **Instance size?** t4g.large default; t4g.medium budget option
  (COSTS.md).
- **A UI password** (you can generate one) and, later, whether they
  want a domain in front of the UI.

## 1. Prerequisites check (run these; walk through gaps)

```bash
aws sts get-caller-identity        # AWS CLI configured?
```
- **No AWS account/CLI?** Walk them through: create an account at
  aws.amazon.com → IAM user or SSO with AdministratorAccess (or at
  minimum CloudFormation/EC2/IAM/SSM permissions) → `aws configure`
  with the access key, secret, and a region (us-east-1 is a fine
  default).
- **Claude subscription?** They need a Claude subscription that
  includes Claude Code usage (Max recommended — see COSTS.md). The
  agents authenticate with a long-lived token generated by
  `claude setup-token` (next section). If `claude` isn't installed
  locally: https://claude.ai/install.sh installs the CLI; sign-in uses
  their claude.ai account.
- **Alpaca keys?** app.alpaca.markets → sign up (free) → Paper
  Trading → generate API key + secret. For live, keys come from the
  live dashboard instead, and options trading requires the account's
  options approval (levels are granted in the dashboard; multi-leg
  structures need the higher level — the agent discovers and works
  within whatever the account permits).

## 2. Secrets into SSM (before the stack — the instance reads them at boot)

Have the human run `claude setup-token` locally (it opens a browser,
they approve, it prints a long-lived token — that token is what lets
the headless agents authenticate against their subscription).

Then (region must match where you'll create the stack; never echo the
values back into the conversation more than needed, and suggest the
human paste secrets directly into their own terminal):

```bash
P=/alpaca-mind   # the SsmPrefix; change if deploying multiple stacks
aws ssm put-parameter --name $P/ALPACA_API_KEY    --type SecureString --value '<YOUR_ALPACA_KEY>'
aws ssm put-parameter --name $P/ALPACA_SECRET_KEY --type SecureString --value '<YOUR_ALPACA_SECRET>'
aws ssm put-parameter --name $P/ALPACA_PAPER      --type SecureString --value 'true'
aws ssm put-parameter --name $P/CLAUDE_CODE_OAUTH_TOKEN --type SecureString --value '<TOKEN_FROM_claude_setup-token>'
aws ssm put-parameter --name $P/UI_PASSWORD       --type SecureString --value '<CHOSEN_UI_PASSWORD>'
```

## 3. Create the stack

```bash
aws cloudformation deploy \
  --stack-name alpaca-mind \
  --template-file deploy/cloudformation.yaml \
  --capabilities CAPABILITY_IAM \
  --parameter-overrides InstanceType=t4g.large
```
(Deploying a fork? Add `RepoUrl=<your fork's clone URL>` — the instance
clones and runs the repo you point it at.)

Stack creation takes a few minutes; first-boot setup (node, the CLI,
the UI build) takes several more. Outputs:

```bash
aws cloudformation describe-stacks --stack-name alpaca-mind \
  --query 'Stacks[0].Outputs' --output table
```

## 4. Watch it come alive (SSM Session Manager — no SSH anywhere)

```bash
IID=<InstanceId from outputs>
aws ssm start-session --target $IID    # interactive shell, or:
aws ssm send-command --instance-ids $IID --document-name AWS-RunShellScript \
  --parameters commands='tail -40 /var/log/alpaca-mind-setup.log'
```
Setup ends with a completion banner. Then verify, in order:
1. `systemctl is-active mind-supervisor mind-sentinel ui-supervisor ui-web`
   → four × `active`.
2. `journalctl -u mind-supervisor -n 20` → a `launch awakening` line,
   then `session done exit=0` (the trader's first session takes a few
   minutes — it is meeting the world).
3. After the awakening completes, `journalctl -u ui-supervisor -n 20`
   → `launch construct` (the UI manager building the first interface;
   this pass runs long — it is designing, building, and verifying a
   site).
4. Open `http://<PublicIp>/` → Basic Auth (user `owner`, the UI
   password) → first the "awakening" landing page, then the
   constructed interface once the UI pass finishes and restarts the
   site.

If anything fails: the setup log names the step; OPERATIONS.md has the
diagnostic patterns.

## 5. Hand over

Tell your human, in your own words, all four of:
1. **The link and password** — and that the interface will keep
   growing on its own; the inbox is where they steer it.
2. **The kill switch** — one command stops all trading instantly:
   `aws ssm send-command --instance-ids <IID> --document-name AWS-RunShellScript --parameters commands='sudo -u mind touch /srv/mind/workspace/state/HALT'`
   (remove the file to resume).
3. **The domain offer** — if they want `mind.theirdomain.com`: point
   an A record at the public IP, then put a TLS proxy (e.g. Caddy) in
   front, or an ALB + ACM certificate. Offer to do it; it is optional.
4. **The removal protocol** — verbatim: *"If you ever want this
   removed completely to stop all charges, tell me to start the
   removal protocol"* (REMOVAL.md).

Finally — only after a successful deployment — you may ask: *"If this
project served you, would you like me to star the repository on your
behalf?"* Do it only with their yes.
